# 컨텍스트 조립

"채팅이 길어지면 AI가 멍청해진다"는 피드백과, 모델을 중간에 바꿀 때의 문제를 함께 해결한다. 근거: [ADR 0003](../decisions/0003-stateless-ai-calls.md).

## 원칙

- CLI 세션을 이어 쓰지 않는다. `--continue`, `resume`을 쓰지 않고 매 호출이 새 세션이다.
- 앱이 매번 아래 묶음을 새로 조립해 보낸다.
- AI가 쓴 글을 대화 기록으로 다시 보내지 않는다. 그 글은 원고에 있고, 사용자 수정까지 반영된 원고 자체가 기억이다.

## 매 호출 묶음

1. 세계관 (`world.txt`)
2. 문체 (`style.txt`)
2-1. 작가 메모·줄거리 계획 (`notes.txt`) — 시놉시스·플롯을 담는 곳. 앞으로의 일도 들어 있어 현재 화보다 앞서 나가지 말라고 함께 지시한다 (2026-10-18 추가)
3. **현재 회차 시점의** 인물·관계 (`graph.json`에서 현재 챕터에 유효한 것만)
4. 앞 챕터 요약들 (`*.summary.txt`)
5. 현재 챕터 원고. 길면 뒷부분만.
6. 최근 지시 몇 개 (`chat/*.jsonl`의 마지막 N개)
7. 이번 요청

## 효과

- 대화를 아무리 오래 해도 보내는 양이 일정하다.
- 모델을 바꿔도 새 모델은 같은 묶음을 처음 받는 것뿐이라 손해가 없다. 그래서 "첫 채팅 후 모델 잠금"은 필요 없다.
- 미래 회차의 관계를 보내지 않아 앞뒤가 맞지 않는 전개를 줄인다.

## 설정 노트 고르기 (2026-10-18 갱신)

세계관·메모 문서 대신 설정 노트를 보낸다. [ADR 0011](../decisions/0011-setting-notes-and-server-side-note-selection.md)

- `[설정 노트 목록]`: 모든 노트의 "폴더 › 제목: 한 줄 요약". 항상 들어간다.
- `[설정 노트 본문]`: 노트가 20,000자 이하면 전부. 넘으면 고정 노트 → 사용자가 붙인 노트 → AI 선택 호출(실패 시 낱말 일치) 순서로 20,000자까지.
- 편집 중인 노트는 목록·본문에서 빼고 편집 대상으로 따로 보낸다.
- 문체·노트를 고칠 때는 문체·노트·관계도 전체·대상 문서만 보내고 화 요약은 보내지 않는다.
